# Supermoon 模式

Supermoon 模式是 Kimi Code 的"极致穷尽"模式。开启后，代理会对每个实质性任务主动规划多智能体协作，而无需等你要求：它会把任务拆解、并行派出独立子代理、并对结果进行对抗性核验——目标是产出最彻底、最正确的结果，而不是最快或最省的结果。Supermoon 还会在模式激活期间把模型的思考强度（thinking effort）锁定到其支持的最高档位，并在模式关闭时恢复你之前的设置。

## 何时使用 Supermoon

当"答案的正确性"比"成本"更重要时使用 Supermoon：

- 审查或评审大规模改动，漏掉一个发现可能代价高昂。
- 排查跨多个文件、多个平台、难以复现的 Bug。
- 准备发布或设计评审，需要全面覆盖与交叉核验。
- 任何你原本打算手工多轮复查的任务。

Supermoon 开启期间，你无需主动要求多智能体协作——模式本身就是常驻指令。当任务很小，或你想让 token 消耗更可预测时，请关闭它。

## 开启与关闭

Supermoon 模式通过 `EnterSupermoonMode` 和 `ExitSupermoonMode` 两个工具控制：Agent 用 `EnterSupermoonMode` 开启模式，用 `ExitSupermoonMode` 关闭模式，因此在任务需要最大程度的严谨性时，Agent 可以自行开启。模式会跨轮次保持，直到显式退出。在 Web 界面中，你也可以通过模式菜单切换。

Supermoon 开启期间，底部模式列表会在 `auto`、`yolo`、`plan`、`swarm` 之外额外显示一个 `supermoon` 徽标。

Supermoon 模式是会话级的：开启新会话时会被重置。

## 代理会收到什么指令

开启 Supermoon 时，Kimi Code 会向对话注入一条常驻指令。代理被告知：模式本身就是指令，用户无需主动要求多智能体编排——

- 在每个实质性任务上，默认使用子代理编排：使用 `Agent` 或 `AgentSwarm` 工具把工作拆成不同部分，并行运行独立代理，并交叉核验结果。
- 目标是产出最彻底、最正确的结果。不要为了速度或成本牺牲完整性；正确性与覆盖率优先。
- 仅在会话性对话或琐碎的机械改动时直接处理。
- 在长任务的各阶段之间持续向用户同步进度，而不是把所有工作一次性串完。

### 质量模式

Supermoon 激活期间，代理会对实质性工作应用以下模式：

- **对抗性核验** —— 派出独立子代理挑战并反驳每一条重要发现；只有当大多数反驳尝试失败时才保留该发现。
- **视角多样化** —— 从多个角度（正确性、安全性、性能、可用性）核验工作，使用持不同立场的独立评审者，而不是一个评审者覆盖全部。
- **评审小组** —— 当子代理发现相互矛盾时，召集一个持不同观点的小组子代理，依据证据收敛出最有支撑的结论。
- **循环至尽** —— 持续派出探查子代理，直到连续多轮都没有新发现。
- **覆盖扫描** —— 覆盖任务的完整表面：每个相关文件、每个受影响的平台或模态、每种输入形态。
- **完整性批评者** —— 结束前，派一个专门负责"找缺失"的子代理：未读的来源、未运行的检查、未核验的主张。
- **不做隐性上限** —— 不要在凑够某个整数个代理或发现后就悄悄停下；只有工作真正穷尽或受用户约束限制时才停止。

关闭 Supermoon 时，常驻指令被移除，恢复默认规则：只有在你明确要求时，或符合常规 `Agent`/`AgentSwarm` 工具规则时，代理才会使用子代理编排。

## 思考强度

进入 Supermoon 时，会把当前模型的思考强度设置为支持的最高档位，让模型在回答前可以投入更多 token 进行推理。退出时恢复你之前的设置。如果当前模型不声明支持可配置的思考强度档位，则不修改该设置。
